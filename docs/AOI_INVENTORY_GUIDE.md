# 🦋 葵ちゃん用ガイド：在庫を一緒に数える（HW部材集計アプリ）

アキヤさんに「在庫集計をやろう」と言われたら、このページの手順で進めてね。
アプリの「📥 在庫データを取り込む」で読み込める **JSONファイル（hw-parts-ops v1）** を作るのが葵ちゃんの役目です。

> ⚠ このリポジトリは**公開**です。本当の単価・お客様の名前や住所・現場の情報は、このリポジトリ（ドキュメントやサンプル）に**絶対に書かない**こと。下の例の数字・名前はすべて架空です。作ったJSONはアキヤさんに渡すだけで、リポジトリには入れません。

## 何のため？
棚卸し（実際に数えた数）や、買った分・使った分を、アプリの在庫にまとめて反映するため。手で1つずつ入力しなくて済みます。

## 手順
1. **アキヤさんが送る**：在庫の写真・メモ・リスト・声（「エルボ20Aが12個、ソケット20Aが5個…」など）。
2. **葵ちゃんが部材を特定する**：部材の `id` を調べる（下の「id の調べ方」）。数や部材があいまいなら、**作る前にアキヤさんに確認**する。
3. **葵ちゃんが JSON を作る**：下の形式で、ファイル名は例 `hw-ops_2026-11-03_count.json`。中身は JSON だけ（コメント・末尾カンマなし）。
4. **アキヤさんが取り込む**：アプリ →「📥 在庫データを取り込む」（在庫タブ、またはデータ管理）→ ファイルを選ぶ。
5. **プレビューで確認** → 「取り込む」。間違えたら **8秒以内なら取り消し**できる。

## JSON の形（hw-parts-ops v1）

```json
{
  "type": "hw-parts-ops",
  "version": 1,
  "id": "2026-11-03-count-sample",
  "date": "2026-11-03",
  "memo": "棚卸し サンプル",
  "ops": [
    { "kind": "count", "id": 1, "qty": 12 },
    { "kind": "count", "id": 2, "qty": 0 },
    { "kind": "add",   "id": 3, "qty": 5, "shop": "サンプル商店" },
    { "kind": "use",   "id": 4, "qty": 2 },
    { "kind": "newItem", "name": "テスト用パッキン", "size": "20A", "cat": "その他",
      "unit": "piece", "price": 100, "stock": 10 }
  ]
}
```

| キー | 必須 | 内容 |
|---|---|---|
| type | 必須 | 固定 `"hw-parts-ops"` |
| version | 必須 | 固定 `1` |
| ops | 必須 | 操作の一覧（1〜300件） |
| id | 推奨 | ファイルごとに新しい文字列（60字まで）。同じ id を2回入れると「取り込み済み」と警告される |
| date | 任意 | `YYYY-MM-DD` |
| memo | 任意 | メモ（60字まで）。在庫の履歴に残る |

### ops の種類（kind）
| kind | 意味 | 必要なもの |
|---|---|---|
| `count` | 棚卸し：数えた数に**置き換え** | id（または name＋size）, qty ≥ 0 |
| `add` | 入庫：買った分を**足す** | id/name, qty > 0（任意 shop） |
| `use` | 使った分を**引く** | id/name, qty > 0 |
| `newItem` | 新しい部材を登録 | name, price（0以上の整数・税別）, 任意 size/cat/unit/packLen/stock/reorder/shop/aliases |
| `alias` | 別名・購入先だけ登録 | id/name, aliases か shop |

日本語の kind（棚卸し・入庫・使用・新規・別名）も使えます。

- `qty` は数字。**長物（メートル品）は m 単位**（例 `62.5`）。
- `aliases`：別名の配列。次から名前で探せるようになる。
- `price` は `newItem` だけ。既存部材の単価は変わりません。
- `unit: "m"` の新規部材は `packLen`（購入長m）が必須。

## id の調べ方
- アプリ本体 `hw-parts-calculator.html` の `let materials = [ … ];` の1行に、初期部材（id 1〜131）が入っています。
- アプリで後から追加した部材（id 132〜）はアキヤさんのスマホの中だけ。名前（name＋size）で指定するか、アキヤさんにバックアップファイルをもらって確認する。
- `name` で指定するとき、候補が複数（例「HI エルボ」だけ→20A/25A…）だとエラーになる。**迷ったら id で**。

## 作る前のチェック
- [ ] `type` / `version` / `ops` がある、JSONとして正しい
- [ ] id はファイルごとに新しい
- [ ] 数があいまいな行は確認済み
- [ ] 棚卸しは `count`（置き換え）、買った分は `add`、使った分は `use` を使い分けた
- [ ] 本当の単価やお客様情報をリポジトリに書いていない

## アプリ側の安全装置
- 壊れたファイルはエラー表示だけで、データは変わらない
- 取り込む前にプレビュー（前→後の在庫）。行ごとに外せる
- 取り込み後8秒は全部取り消せる
- 在庫未設定の部材への `use` は飛ばされる（`count`/`add` は設定される）

## 📝 手書きの在庫表（写真・スキャン）から JSON を作る（v1.9〜）
アキヤさんはアプリの「📝 手書きの在庫表を印刷」で紙を印刷して、数を手で書き込みます。その紙の**写真かスキャン**が届いたら、次のように作ってね。

- 表の左の **「番号」= 部材の `id`** です。名前ではなく**番号で** `{ "kind": "count", "id": 番号, "qty": 数 }` を作る（名前は似たものが多いので照合用にだけ使う）。
- 「数量」欄に書かれた数をそのまま `qty` に。単位欄（個・本・m・巻・枚・箱・袋・組・セット など。部材ごとにアキヤさんが選べる）の単位で数えた数なので、換算せずそのまま入れる。`m` の行は小数OK。
- **空欄の行は op を作らない**（数えていない＝在庫は変えない）。「0」や「なし」「—」と書いてあれば `qty: 0`。
- **読めない・あいまいな数字（例：1か7か、6か0か、消し線、はみ出し）は推測しない。** その行は JSON に入れず、**「要確認」リスト**（番号・品名・読めた候補）にしてアキヤさんに聞く。答えをもらってから追加する。
- 番号と品名が合わない（例：番号が欄外で読めない）ときも **要確認**。
- 記入日は `date`、記入者や「手書き在庫表から」は `memo` に入れる。ファイル名例：`hw-ops_2026-11-03_count.json`。
- 返すときは「取り込める行 ○件／要確認 ○件（一覧）」を先に伝えてから JSON を渡す。

例（架空の数字）：
```json
{
  "type": "hw-parts-ops",
  "version": 1,
  "id": "2026-11-03-handsheet",
  "date": "2026-11-03",
  "memo": "手書き在庫表から",
  "ops": [
    { "kind": "count", "id": 1, "qty": 12 },
    { "kind": "count", "id": 13, "qty": 7.5 },
    { "kind": "count", "id": 38, "qty": 0 }
  ]
}
```
要確認：`#21 ストリートエルボ (20A)` … 「4」か「9」か読めません。
