# 一般見積り・請求書モード 仕様（第1歩）

日付: 2026-11-11（Asia/Tokyo）
対象アプリ: `hw-parts-calculator.html`（公開リポジトリ。URLは変更しない）
本番: いまは v1.9（main）。この仕様と第1歩の実装は **マージGOがあるまで本番に出さない**。

## 目的
1つのアプリから、「HW部材集計」（今までどおり）と、「一般の見積書・請求書」を選べるようにする。
使う人: アキヤさん（スマホ・タブレット中心、コードは書かない）。

## 壊してはいけないもの
- いまの HW部材集計の動きと、端末に保存済みのデータ（部材・数量・在庫・過去の集計・宛先・工事価格表）。
- 公開リポジトリに、本物の単価表ファイル（xlsx）・お客様の情報・鍵を入れない。
- ブックマーク用URL（GitHub Pages の今のアドレス）は変えない。

## 完了条件（第1歩）
起動時にモードを選べ、HW側のデータは触れずに一般モード用の部材リスト（HWからのコピー）を追加・編集・削除できる。見積書・請求書の本作成は第2歩。

---

## 事実（コードと現行アプリを見て確認した）

- アプリは単一HTML。保存はすべてこの端末の localStorage。サーバーには送らない。
- HWの保存キー（第1歩でも名前も中身の構造も変えない）:
  - `hwParts.workState.v1` … 部材・数量・在庫・過去の集計・税率など（保存形式 v:3）
  - `hwParts.printParties.v1` … 集計表の宛先・発行元
  - `hwParts.sizeOpen.v1` … サイズグループの開閉
  - `hw_price_table_v1` … 工事価格表（端末内だけ。リポジトリには入れない）
- 部材の項目（名前・種類・規格・単価・入数・数え方の単位・配管フラグなど）は `materials` 配列で持っている。
- 起動時は保存済みの HW 状態を読んで、すぐ部材表を出している（モード選択画面はまだない）。
- 消費税の入力欄は集計バーにあり、初期値は 10%。計算は現行の集計表どおり（行金額を円に丸めて合計）。
- 印刷はブラウザの「印刷 / PDF」。専用の PDF ライブラリは使っていない。

## 決めたこと（アキヤさんの依頼に基づく。第1歩で実装する）

- 起動時にスタート画面を出し、「HW部材集計」か「一般見積り・請求書」を選ぶ。
- 「次回からこのモードで開く」は任意（初期はオフ＝毎回選ぶ）。どちらにしても「モードを選ぶ」でスタート画面に戻れる。
- HWモードは、今のアプリの機能とデータをそのまま使う。
- 一般モードの部材リストは、**初めて開いたとき**に HW の部材マスターをコピーして作る。
  - コピーするもの: 名前・種類・規格・数え方・単位・入数、および **アプリ内のHWマスターが持っている単価**。
  - コピーしないもの: 使用数・在庫・在庫履歴・過去の集計。工事価格表のxlsxはコピーもリポジトリ追加もしない。
- その後の追加・編集・削除は、HW と一般で完全に別。片方を直してももう片方は変わらない。
- 既存の HW データは破壊しない。一般モードを初めて作る前に、HW の保存キーを端末内へバックアップする（上書きしない、1回だけ）。
- アプリ全体の呼び名（スタート画面）は **「見積り・請求書」**（案）。モード名は従来どおり「HW部材集計」と「一般見積り・請求書」。リポジトリ名と公開URLは変えない。
- 見積書・請求書の作成は第1歩ではスケルトン（「次のステップで用意します」）にとどめる。

## 推測・前提（70%以上の確信。違う場合は第2歩で直す）

- 一般モードのホームは、まず部材リストの管理が中心（見積・請求は第2歩）。
- 一般モードでは、在庫・手書き在庫表・工事価格表・過去のHW集計・声で入力は出さない（HW専用の機能のため）。
- 「次回からこのモードで開く」の初期はオフの方が安全（うっかり違うモードで開いて戸惑わない）。
- 一般モード用のバックアップ読み書きは、HWのバックアップと混ぜると危険なので第1歩では出さない。

## やらないこと（第1歩の範囲外）

- 公開URLやリポジトリ名の変更。
- 本番（GitHub Pages / main）への反映（アキヤさんのGOが必要）。
- 本物の価格表ファイルをリポジトリに入れること。
- HW側の保存キーの名前変更や、保存済みHWデータの書き換え（読み取りと、端末内バックアップのみ）。
- 在庫機能の一般モードへの移植。

## 手順

1. 仕様をこのファイルに書く（本ファイル）。
2. スタート画面・モード分離・一般部材マスター（コピー＋追加/編集/削除）を実装する。確認: 自動テスト（モード隔離・移行の安全性）と、ヘッドレスブラウザの画面確認。
3. 見積書・請求書の本作成（質問の回答後）。確認: 架空データでの印刷プレビュー。**承認待ち（本番反映は別途GO）**。

## 保存キー（第1歩で追加するもの）

- `appSelect.v1` … 最後に選んだモードと、「次回からこのモードで開く」か。
- `genParts.workState.v1` … 一般モードの部材リスト（HWキーとは別）。
- `hwParts.backup.beforeGeneral.v1` … 一般モードを初めて作る直前の、HWキーの控え（1回だけ。中身の上書きはしない）。

## 失敗したときに起きうることと守り方

- 一般の保存を間違えてHWキーに書く → `save` はモードを見て書き先を分ける。テストで「一般を編集しても HW キーがバイト単位で変わらない」ことを確認する。
- コピーのたびに一般リストが初期化される → 一般キーが既にあるときは再コピーしない。
- 移行の途中で失敗する → 先にバックアップを書き、それから一般キーを作る。
